# 多个小程序合并

## 背景

由于历史原因，早期开发者不会使用分包，包体过大时，将部分功能模块拆分成单独的小程序。

开发有串联关系的功能时，就需要修改多个项目，很繁琐。

所以计划将这些拆分出来的小程序，以分包的形式，合并到主小程序中。

## 关键问题与处理

1. 组件兼容
   - 各个小程序里里使用的组件库都是直接从远程仓库备份下来的。部分组件还在各自小程序中做了一些定制化。
     所以想合并后，统一使用主包的组件库，就不可取了。
   - 解决：先比对差异，再保留各分包的组件源码和引用。原本全局注册的 Toast 改为在各页面 JSON 中注册，由用到的页面或组件挂载。
2. 样式与导航栏
   - 主包全局样式会影响普通分包的同名样式。
   - 解决：分包页面显式引入自己的公共样式，覆盖冲突属性。例如问卷页去掉固定内容高度，让背景铺满、内容自然滚动。删除自绘标题和占位，改用微信原生导航栏。
3. 主包大小可能会溢出
   - 解决：分包后没有出现
4. 登录与状态
   - 原先子小程序各有一套登录的配置逻辑，现在需要去除
   - 解决：复用主包的登录和企业切换，移除旧登录与 SSO 入口。账号、Token、当前企业由主包维护。草稿等业务缓存按分包、用户、企业和角色隔离，分包私有 `globalData` 各自维护。
5. 路由兼容
   - 解决：给新分包分配唯一的路径和名称，避免覆盖主包已有分包。五个模块共用一套路由，识别旧 AppID 或 `appCode` 后转为站内跳转，保留业务参数并支持登录后回跳。

## 结果

工作台打开这五个模块已改为主包内部跳转，初步真机验证可行，避免了原有的跨小程序确认弹窗。
