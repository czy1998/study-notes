# 问题记录

## 1. WebView 内 H5 使用 <video>，安卓机型无法触发自动播放

**背景**

H5 内代码如下，在 ios 内能触发自动播放(autoPlay)，安卓内则无法触发

```tsx
<video
  src="xxxx.mp4"
  x5-video-player-type="h5" // 启用H5播放器,是 wechat 安卓版特性
  x-webkit-airplay="true" // 使此视频支持ios的 AirPlay 功能
  webkit-playsinline="true" // 这个属性是ios 10中设置可以让视频在小窗内播放，即不全屏播放
  playsInline // 指明视频将内嵌（inline）播放，即在元素的播放区域内，也就是不会默认全屏播放
  muted // 视频静音
  autoPlay // 自动播放，在某些浏览器（例如 Chrome 70.0）中，如果没有设置 muted 属性，autoplay 将不会生效。
></video>
```

**解决办法**

给 video 添加 ref，在页面挂载后手动去触发播放操作

```tsx
useEffect(()=>{
    ref.current?.play()
},[])

<video ref={vRef}></video>
```

## 3. webview 跳转小程序内部页面，想获取返回结果

**背景**

进入小程序页面 A，A 中有个 webView，此时 webView 访问的是 URL-Q，在这个 webView 里跳转了1次，进入了 URL-W，在 URL-W 中跳转进入了 小程序页面 B 来选择医院，在 小程序页面 B 选择完后，返回上一页回到 页面 A。

此时如何将 页面 B选择的医院，传递给 webview 下的 URL-Q，且不能影响当前 webview 的 history 堆栈

**解决办法**

尝试了下面几种方法，都失败了:

1. 通过公共存储 storage，由于 webview 和 小程序本体，两者存储相互独立，放弃
2. 通过更新 webview 的 url，但是此举会变更 history 堆栈，放弃
3. 通过 postMessage 来传递消息，查阅得知，仅可 H5 -> 小程序，小程序 -> H5 不行，放弃

最后选择后端介入:

1. URL-W 前往 B 之前设置一个 id，传递给 B
2. B 选择完，调用接口，存储数据，关联 id
3. 回到 URL-W 后通过 id，调用接口获取数据

## 4. webview h5 内按钮点击下载 pdf ，window.open、location.href 等办法在安卓机上无效

**解决办法**

在小程序内，添加一个公用下载页面：

1. 点击下载，跳到工具页，url 带上转换后的 文件链接
2. 工具页使用 wx.downloadFile 下载文件

⚠️注意：download 的合法域名

## 5. iphone 访问 webView 显示 “网络出错,无法显示该页面”，删除小程序，刷新都没有效果

**背景**

小程序 A 未登录时，会先转到通用登录页 B 去登录。
iphone 跳转 B 失败，去了一个像是微信内置的页面，就提示 “网络出错,无法显示该页面” ，什么原因也不清楚

**解决办法**

使用 安卓 机子进行同样操作，也是先进入内置的页面，还显示了一个弹窗，提示信息为：

www.demo.com 该网站的安全证书存在问题，可选择“继续”在浏览器中访问

由此得知，是网站证书出了问题。检查得知，证书过期了，更换证书后，即可正常访问页面 B

## 6. 批量修改页面 标题高度、页面上边距

**背景**

小程序 A 由于历史原因，`标题部分` 和 `页面部分` 都是用标签（view）写的，并配置了 `页面内容` 上边距使得 `标题` 可以不遮挡 页面
小程序运营好几年，只有这一个客户反馈页面遮挡（特定的 vivo 手机），由于没有样机，只能提供一个处理方案，来修改小程序内的所有页面

**解决办法**

- 写一个共用方法 Fn 计算样式
- 创建 `Behavior` 注入页面，包装页面内 `onload`、`onshow` 方法，让页面在触发这俩方法时自动计算样式保存到 `Behavior` 内的属性上，这个属性同样会传入页面（[同名属性规则](https://developers.weixin.qq.com/miniprogram/dev/framework/component-framework/behaviors.html#%E5%90%8C%E5%90%8D%E5%AD%97%E6%AE%B5%E7%9A%84%E8%A6%86%E7%9B%96%E5%92%8C%E7%BB%84%E5%90%88%E8%A7%84%E5%88%99)）
- 修改每个页面的 wxml， js 文件注入 `Behavior`

```js
// util.js
/**
 * 获取自定义导航栏实际占用的顶部高度。
 * 微信返回的尺寸单位为 px，可以直接用于 WXSS。
 */
export function getCustomNavigationStyles() {
  const windowInfo = wx.getWindowInfo();
  const statusBarHeight = windowInfo.statusBarHeight || 0;
  let menuButton;

  try {
    menuButton = wx.getMenuButtonBoundingClientRect();
  } catch (error) {
    menuButton = null;
  }

  // 保持胶囊按钮上下的间距一致，异常坐标下不使用负间距。
  const topGap = menuButton ? Math.max(menuButton.top - statusBarHeight, 0) : 0;
  const navigationHeight =
    menuButton && menuButton.bottom > statusBarHeight
      ? menuButton.bottom + topGap
      : statusBarHeight + 44;

  return {
    title: `height: ${navigationHeight - statusBarHeight}px; padding-top: ${statusBarHeight}px;`,
    page: `padding-top: ${navigationHeight}px;`,
  };
}

function applyCustomNavigationStyles() {
  this.setData({
    navigationStyles: getCustomNavigationStyles(),
  });
}

function wrapPageLifecycle(defFields, name) {
  const original = defFields.methods[name]; // 方法存在于 methods 内部
  defFields.methods[name] = function () {
    applyCustomNavigationStyles.call(this);
    if (typeof original === "function") {
      original.apply(this, arguments);
    }
  };
}

export const customNavigationBehavior = Behavior({
  data: {
    navigationStyles: {
      title: "",
      page: "",
    },
  },
  lifetimes: {
    attached() {
      // applyCustomNavigationStyles.call(this); // 下面已经有包装了，这里就不需要执行了
    },
  },
  definitionFilter(defFields) {
    wrapPageLifecycle(defFields, "onLoad");
    wrapPageLifecycle(defFields, "onShow");
  },
});
```

上述包装页面的 onLoad、onShow ，使得 `Page` 和 `Behavior` 绑定太死，故此对方法做了些调整，如下所示：

```js
export const customNavigationBehavior = Behavior({
  data: {
    navigationStyles: {
      title: "",
      page: "",
    },
  },
  lifetimes: {
    attached() {
      this.setData({
        navigationStyles: getCustomNavigationStyles(),
      });
    },
  },
});
```
