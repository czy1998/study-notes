# 介绍

Model Context Protocol (MCP)，模型上下文协议，旨在实现大语言模型与外部数据源和工具的集成。

简单讲就是可以让智能体 agent 接入更多功能，可以做更多的事。

## 实现一个 mcp (将时间戳转换为 年月日时分秒)

按这个做就能接到本地 Codex。用 **Node + 官方 SDK + Stdio**，只暴露一个 tool。

**约定**

- 入参：`timestamp`，数字。`< 1e12` 当秒，否则当毫秒。
- 时区：`Asia/Shanghai`
- 输出：`2021年01月3日12:33:22`（月补零，日不补零，时分秒补零）
- 日志只能打 `console.error`，不能 `console.log`，否则会破坏 Stdio

**1. 建项目**

```bash
mkdir -p ~/mcp/ts-format
cd ~/mcp/ts-format
npm init -y
npm install @modelcontextprotocol/server zod
```

`package.json` 里加上：

```json
{
  "type": "module"
}
```

**2. 写 `server.mjs`**

```js
import { McpServer } from "@modelcontextprotocol/server";
import { StdioServerTransport } from "@modelcontextprotocol/server/stdio";
import * as z from "zod/v4";

// 创建 MCP Server。name 给 Host 识别，还没开始监听。
const server = new McpServer({
  name: "ts-format",
  version: "1.0.0",
});

// 把 Agent 传来的时间戳转成 Date。
function toDate(timestamp) {
  // NaN / Infinity / 非数字直接拒绝。
  if (!Number.isFinite(timestamp)) {
    throw new Error("timestamp 必须是数字");
  }

  // < 1e12 当秒，否则当毫秒。new Date() 只吃毫秒。
  const ms = timestamp >= 1e12 ? timestamp : timestamp * 1000;
  const date = new Date(ms);

  // 非法值会变成 Invalid Date。
  if (Number.isNaN(date.getTime())) {
    throw new Error("timestamp 无法转换成有效时间");
  }
  return date;
}

// 按东八区格式化成：2021年01月3日12:33:22
function formatShanghai(date) {
  // formatToParts 按字段拆时间，locale 只用稳定结构，最后自己拼中文。
  const parts = new Intl.DateTimeFormat("en-US", {
    timeZone: "Asia/Shanghai", // 固定中国时区，不跟机器本地时区走
    year: "numeric", // 2021
    month: "2-digit", // 01，补零
    day: "numeric", // 3，不补零
    hour: "2-digit", // 12
    minute: "2-digit", // 33
    second: "2-digit", // 22
    hourCycle: "h23", // 24 小时制
  }).formatToParts(date);

  const get = (type) => parts.find((part) => part.type === type)?.value;

  // Number(day) 防止出现 03。
  return `${get("year")}年${get("month")}月${Number(get("day"))}日${get("hour")}:${get("minute")}:${get("second")}`;
}

// 注册给 Agent 调用的 tool。
server.registerTool(
  "format_timestamp", // Agent 调用时用的名字
  {
    // 这段给模型看：干什么、参数怎么理解、返回长什么样。
    description:
      "把 Unix 时间戳转成中国时区的年月日时分秒。小于 1e12 按秒，否则按毫秒。返回如 2021年01月3日12:33:22。",
    // 入参 schema，Host 会发给 Agent。
    inputSchema: z.object({
      timestamp: z.number().describe("Unix 时间戳，秒或毫秒"),
    }),
  },
  async ({ timestamp }) => {
    try {
      const text = formatShanghai(toDate(timestamp));
      // MCP 规定成功时返回 content 数组。
      return { content: [{ type: "text", text }] };
    } catch (error) {
      // 失败不要把进程打崩，用 isError 告诉 Host。
      return {
        isError: true,
        content: [{ type: "text", text: error.message }],
      };
    }
  },
);

async function main() {
  // 本地 Stdio 传输。之后 stdin/stdout 归 MCP 协议占用。
  const transport = new StdioServerTransport();
  // 挂上后，Codex Host 会为它创建一个 MCP Client。
  await server.connect(transport);
  // 只能打 stderr。console.log 会污染 stdout，导致协议解析失败。
  console.error("ts-format MCP server started");
}

main().catch((error) => {
  console.error(error);
  process.exit(1);
});
```

**3. 先用 Inspector 测，不要直接接 Codex**

```bash
cd ~/mcp/ts-format
npx @modelcontextprotocol/inspector node ./server.mjs
```

浏览器打开后：

1. 连上这个 Server
2. 调 `format_timestamp`
3. 传入 `1609648402`
4. 应返回 `2021年01月3日12:33:22`

不对就先修 Server，别急着加到 Codex。

**4. 接到本地 Codex Host**

用绝对路径，nvm 用户建议把 `node` 也写成绝对路径：

```bash
which node
# 例如 /Users/mac/.nvm/versions/node/v22.19.0/bin/node

codex mcp add ts-format -- /Users/mac/.nvm/versions/node/v22.19.0/bin/node /Users/mac/mcp/ts-format/server.mjs
```

确认：

```bash
codex mcp list
codex mcp get ts-format
```

应看到 `ts-format`，类型是 `command`，不是 `url`。

**5. 在 Codex 里用**

1. **新开一个会话**，旧会话不会自动加载刚加的 MCP
2. 问：`把 1609648402 转成年月日时分秒`
3. Agent 应调用 `format_timestamp`
4. 结果应是 `2021年01月3日12:33:22`

**对照关系**

- 你写的 `server.mjs` = MCP Server
- Codex 桌面端 / CLI = Host
- `codex mcp add` 之后，Host 会为它创建一个 MCP Client
- 通信是 **Stdio**，Codex 负责拉起这个 Node 进程

**常见坑**

- 用了 `console.log`：MCP 直接坏掉
- 给了相对路径：Codex 启动 cwd 不对，找不到文件
- nvm 的 `node` 不在 Codex 的 PATH 里：用 `which node` 的绝对路径
- 加完 MCP 没新开会话：工具列表还是旧的
- 传了毫秒却按秒解析：这个实现已按 `1e12` 自动判断

先跑通 Inspector，再 `codex mcp add`。这一步顺序别反。
